# Island 线程资源的条件性决策 · 2026-09-12

S03 本轮选择保留每个原生 Island 的独立执行线程，以及已验收的父调度器事件门控；不引入通用有界线程池。已有 CPU、短任务和空闲三类数据确认线程资源成本，也确认当前接口缺少保证线程池整体进展所需的宿主约束。该条件性扩展形成明确结论，S02 的同 Island 调度优化继续独立推进。

## 数据与适用范围

[原始资源报告](island-resource-report-20260910.md)保留 224 次独立进程执行，含 192 次正式样本，全部输出正确。CPU 总工作量扩大八倍时，VM/JIT 配置的冷进程吞吐分别达到单 Island 的 6.92 倍和 7.48 倍。128 个短任务的 VM/JIT 冷进程中位耗时约 17.8/19.7 ms；该口径包含加载、创建、计算、传输及退出。

独立历史资源快照中，128 个空闲 Island 对应 129 个线程，VM/JIT 的增量 RSS 约 65/76 MiB。该快照曾与构建重叠，只用于进程资源观察。RSS 包含独立 VM、堆及执行状态，不能全部归入线程栈，也不能全部计作池化可节省量。

[事件门控报告](island-event-gate-report-20260911.md)已证明无需迁移 VM 就能降低父调度器的无效工作：128 个空闲子 Island 的父空轮询减少约 97%；780 次对照与 186 次独立复测全部正确。已保留该实现。

## 当前契约的具体限制

`vo-common-core::ExternEffects` 声明让出、排队、IO/宿主等待、重放、闭包回调和退出。它没有“宿主线程绝不阻塞”或“可跨线程迁移”的声明。`os::blocking_fileRead` 声明 `MAY_WAIT_IO_REPLAY`，但标准输入路径仍同步执行 `std::io::stdin().read`。因此，不能根据等待效果位直接把 Island 纳入有界合作式工作池。

若池中的每个工作线程都阻塞在外调，而解除阻塞的 guest 工作排在同一池中，池无法保证进展。这个反例不依赖测量快慢。为每个可能阻塞的调用无限增加替补线程，会失去有界资源目标；单靠超时也无法安全抢占任意原生外调。

原生 `math/rand` 的默认状态由 `NATIVE_RNG` 线程局部变量持有。复用线程或迁移 Island 会改变状态归属。扩展 ABI 的宿主服务桥虽然在每次调用建立可嵌套的 TLS scope，并在返回或展开时恢复，但这条规则只管理桥本身；它没有承诺任意扩展的私有 TLS 都可迁移。需要先明确状态属于进程、线程、VM 还是 Island，才能设计迁移。

当前销毁过程还要求停止并等待子线程后释放服务所有者。中断入口支持单独的原子标记，空闲等待用有界轮询观察它。池化需要重新规定正在执行、已停放、排队和取消之间的所有权及唤醒竞态，不能只替换线程创建入口。

## 重新启动的条件

只有在代表性应用显示大量长期空闲/短任务 Island 的资源成本构成实际限制，并且以下接口准备齐全时，才重新启动池化实现：

1. 外调能显式声明阻塞及线程亲和属性；未知扩展保留专用线程，合作式执行有可验证的准入边界。
2. VM/Island 状态和 RNG、宿主服务、回调、扩展 TLS 的归属明确；任意时刻保持单执行者和独立堆。
3. 阻塞外调、回调嵌套、取消、退出和服务释放都有有界进展规则及实际反例测试。
4. 三类现有负载保持对照，并分开测 VM/堆与线程资源；CPU 吞吐、取消延迟和宿主进展作为共同出口。

本次没有创建线程池原型，也没有给线程池声称任何加速或内存收益。决策基于已有测量和现存契约的可执行反例；不把通用池的困难扩展成对专用合作式宿主的结论。
