# R04 局部表示与动态分配边界 · 2026-09-12

本轮保留已验收的不可变字面量复用、局部固定数组表示和紧凑描述符。动态字符串/切片视图及一般堆对象继续执行原有分配与准入，不增加一套延迟物化协议。这部分条件性选择已经明确；最新组合产品的正确性和累计性能出口仍开放。

## 可观察行为决定表示边界

当前 Accepted 规范 [runtime-memory §3.1–3.4](../lang/docs/spec/runtime-memory.md) 明确了四种情况：

| 对象或表达式 | 已选表示 | 必须保留的边界 |
| --- | --- | --- |
| 不可变字符串字面量 | Island 内有界弱复用；Core 可引用镜像常量 | 命中无分配；缺失按真实分配准入；代际、模块与所有权有效；sticky 错误先终止后续效果 |
| 不逃逸的局部固定数组 | 精确类型的连续帧槽；独立 RHS 快照 | 声明前初始化次序、别名和根；逃逸/切片/捕获等边界保留 canonical 存储；帧容量仍受限 |
| 非空动态字符串/切片视图 | 紧凑的稳定堆描述符，共享已验证布局事实 | 原分配入口、allocation_allowed、硬限额、精确统计、原 owner、范围与写屏障 |
| 需要独立身份的一般堆对象 | canonical 稳定堆对象；允许有证明的字段值优化 | 真实准入时点、地址身份、独立可变状态、精确 GC 和失败后的效果顺序 |

将后两项一律改成帧内值，并在逃逸时才创建堆对象，会改变现有可观察行为。一个直接反例是先创建非空字符串，随后关闭分配，再求它的完整非空切片。当前入口必须产生 `AllocationForbidden`；局部描述符若直接成功，就越过了这个边界。即使最后没有返回或保存该视图，错误本身及后续语句是否执行仍可观察。

提前保留额度、退出时补充统计也不能替代原操作：限额以真实 managed committed bytes 为准；分配计数统计实际存储操作；GC 债务、collector 工作容量和 sticky 错误都有指定时点。把实际分配推迟到一个有后续效果的逃逸点，会改变首先失败的操作及已执行的语句。

## 已有反例与验收证据

[字符串视图拥有者测试](../lang/crates/vo-runtime/src/objects/string.rs) 的 `compact_views_preserve_allocation_admission_and_sticky_failure` 覆盖精确对象容量、`MetadataExhausted`、非空视图禁分配失败，以及空串/无效范围的既有行为。[Core 宿主测试](../lang/crates/vo-web/tests/aot_memory.test.mjs) 覆盖分配禁止、原始 owner 释放和错误保留。[局部数组语言用例](../tests/lang/cases/runtime/core/backend_local_arrays.vo) 与 [切片视图用例](../tests/lang/cases/runtime/core/backend_slice_views.vo) 分别约束帧内快照和逃逸存储。

这些测试属于各自已保存的完整产品验证；本文没有声称进行了新的测试运行。局部固定数组的 v2 产品有 8,293 项完整检查和 61 项七后端 11,956 次性能对照；后续来源/Map/VM/动态缓存产品也保留相应完整语言覆盖。具体绑定与分项收益见[局部数组报告](local-array-benchmark-report-20260912.md)、[字面量报告](literal-reuse-report-20260911.md)和[实施总表](toolchain-optimization-progress-20260909.md)。当前源码里的周期代际恢复还需完成新组合验证。

## 本轮实施决定

动态视图的收益继续来自已经实施的 R03 描述符缩小、公共元素布局、直接几何访问和 R01 分配路径，保留原来的分配时点。一般对象的标量值传播与字段优化继续保留 canonical allocation，避免引入第二份身份或统计权威。

不新增动态视图延迟物化和一般堆对象分配消除。重新打开这个方向需要明确的新语言/宿主契约：哪些表达式允许改变分配次数、禁分配行为、身份与错误时点，以及跨全部后端的兼容规则。单个热点上的速度收益不足以代替这些条件。本决定限定这一表示方向；X04 的运行时帧与 X05 的生成分配许可仍按各自协议继续实验。
