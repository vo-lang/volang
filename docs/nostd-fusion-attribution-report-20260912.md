# no_std 融合撤回：三版本归因 · 2026-09-12

六参数 float64 闭包在最后组合中相对融合实验版变慢，主要对应已撤回融合的局部收益。与融合前版本直接配对时，单一目标变化 +0.10%（95% −0.18%～+0.38%），阶段变化 −0.30%（−0.74%～+0.10%）；两者区间均包含零。这不证明所有 no_std 变化都由融合解释。

维持撤回融合的决定：这次同一批三版本对比中，融合令 `jit-call` +5.71%、`sum-array` +3.59%、float32 宽闭包单一/阶段目标 +2.57%/+2.36%、整数宽闭包阶段目标 +4.30%。先前全目录独立复测另确认 25 组回退；不能为 float64 局部收益重新引入这些代价。

最终组合相对融合前仍有正区间：例如 `map-interface-keys` +2.25%、`scalar-chain-1` +2.76%、`sum-array` +1.01%。Map 分布诊断已显示 interface-int 连续键的探测代价与对齐输入的大幅改善并存；这里的整体组合对比不能独立分离 hash、异常状态表示和代码布局各自的耗时贡献。其余小幅变化一并保留，未将未定位的成因写成结论。
