## 最终状态 · 2026-09-12

本机本轮工作已完成。28 个工作包的采用与合理不扩张决定见[最终决策](toolchain-optimization-package-decisions-20260912.md)，七后端原始 21 项直接对照、编译成本和生成物代价见[最终报告](toolchain-final-performance-report-20260912.md)。最终 Core 修正重新通过 315 项所属 Rust 测试和 2,430 项产品检查；v1 的 2,617 次 Rust 与 8,355 项完整产品检查单独保留。

用户明确要求平衡复杂度和性能。最后采用较简单的整数索引与比较方案，接受相对 P8 约 +2.24%/+6.25% 的两项整数查询取舍，保留浮点及删除重插入场景的主要收益；独立探测循环等后续试验未合入。没有继续追逐微小回退，也没有重启整套优化实验。

另一原生架构的实际执行仍缺环境，这是外部覆盖边界。下方“待完成”“继续”“预计”等文字保留当时的实施过程；当前完成状态和后续范围以本节及最终决策为准。

## R01 实验决策

最初尝试的“形状重复一次后重开区域”在逐个交替时改善，但每两个对象切换仍出现显著浪费，已撤回。探索数据保存在 `rejected-shape-repeat/`，不作为最终性能结论。

当前方案使相同大小、不同类型的对象共享区域，在位图发布前写入精确 ValueMeta；布局大小、槽数、颜色和 value-slots 标记继续保持一致。不同大小触发退避时，必须以本次实际预留量衡量利用率：位图边界可能只提供一个或几个单元，固定按 32 个空余单元判定会漏掉这些情况。回归测试覆盖了这一缺陷。

其余工作包仍开放。最终收益需要串行、绑定源码和产物身份的前后采样；跨后端语义、生成代码覆盖、内存限额及 GC 压力验证完成后再更新阶段验收。
