# 执行状态与调度架构复核 · 2026-09-12

这份记录限定剩余 X04、X05、S02 的决策边界。帧缓存的完整冷、热比较与局部唤醒工作量对照均已完成。本文明确这一轮采用和拒绝的设计，端到端耗时及组合正确性由最终产品验收收口。

## Core 帧：现有能力与剩余成本

`FunctionCapabilities` 已分别描述分配、挂起、异常和调用栈观察；`materialized_functions` 据此选择持久帧。封闭的普通调用可以使用直接 ABI；固定局部数组和静态字面量返回已有专门证明。递归纯函数还可使用可重试的直接适配器，其白名单已经允许一部分托管对象读取。

当前保留持久帧的主要约束有：分配触发的有界 GC、递归 Wasm 栈深度、预算耗尽、defer/recover 和 Caller。`materialized_functions` 明确保留这些情况，并沿调用图传播必要条件。完整的根记录、逻辑帧与挂起状态拆分，需要在实际挂起点保存每层调用的继续位置和值；仅保留 GC 根无法恢复已经退回宿主的 Wasm 调用栈。

历史逐函数诊断使用其冻结镜像，二叉树 `makeTree` 产生 6,444,382 个帧，检查函数产生 43,682 个帧；递归树 `insert` 产生 13,390,774 个帧，其三个纯查询函数各 56,983 个。原始记录为 [逐函数工作量](../target/bench/runs/toolchain-optimization-20260909/core-frame-functions/results.json)。这些数字属于该记录绑定的镜像，不冒充最新组合产品的重新采样。

这个分布说明，仅扩大纯查询函数的直接调用范围很难覆盖主要成本。构造和插入函数包含分配或可见写入；中途退出后从入口重试会重复已经完成的操作。若引入更广泛的直接执行区域，至少需要同时证明：

- 全部操作和传递调用的执行预算有界，进入前可以判断剩余预算。
- 准入失败可以在任何副作用发生前回退；实际分配仍按原次序执行，保留 sticky OOM。
- 根更新、逻辑来源、嵌套异常和实际挂起有唯一的恢复表示。
- 递归与循环不会把有界片段扩大成无界宿主停顿。

现有两个帧复用实验覆盖更直接的物理成本。八项弱缓存减少重新分配，保留逐次宿主调用；单帧生成代码方案还能省去部分宿主调用，但命中范围更窄。两者的完整正确性和工作量见[帧实验记录](core-frame-cache-experiments-20260912.md)。两份方案都不采纳：弱缓存的递归树冷/热耗时增加约 9.07%/9.24%；生成代码复用增加约 43.86%/44.61%。两轮各 61 项冷比较及三方案热比较输出全部正确，仍无法满足性能标准。缓存元数据、页保留、GC、宿主调用和每项耗时均见[完整冷报告](core-generated-frame-cold-report-20260912.md)与[完整热报告](core-frame-warm-comparison-report-20260912.md)。保持 ABI9。

## 调度：局部成本与服务边界

当前 FIFO 就绪队列已有常数时间出队，短 Fiber 的存储也按调度器预算复用。`run_scheduling_loop` 在片段间处理终止状态、取消、宿主 quantum、有界根扫描、Island 命令和 I/O。接收方被唤醒后进入队尾；直接优先执行它会改变现有公平性。保留 FIFO 的交接仍须服务这些边界，不能把它们从计时路径中删除。

[执行诊断](execution-diagnostics-report-20260912.md)记录无缓冲 512 条消息约 1,029 个调度片段、64 个短任务约 65 个片段。计数明确区分了真实执行层级，部分配置在低进展退避后由解释器执行。这些片段数量证明存在调度成本，尚未单独量出每个检查占总耗时的比例。

局部唤醒候选首先消除可直接证明冗余的临时分配：单个唤醒无需分配重复检查集合，没有远程授权依赖时无需建立授权工作区，全部唤醒都在本 Island 时直接复用已持有的顺序数组。每个请求和等待者身份仍完整验证，远程操作继续完成全部可失败准备后再提交。[实际工作量对照](local-wake-work-report-20260912.md)已完成：24 次独立执行中，channel/select 宿主分配次数减少 83.33%/55.55%，分配字节减少 77.84%/74.48%；全部 managed/GC、调度片段及指令计数相同。任务回收与计算控制项相同，执行结束时宿主净保留字节相同。所属 VM/Engine 和配置检查通过，端到端性能进入最终组合。

若这一步后短任务仍由调度片段成本主导，再考虑统一循环内的有预算批处理。新的批处理必须消费原有宿主 quantum，保持 FIFO，并在取消、待处理根扫描、显式 GC、宿主等待或跨 Island 操作处退出。第二套独立调度循环会复制这些规则，应避免引入。

## 本轮架构决策

X04 保留已经实现的精确根、逻辑来源和执行效果边界，继续使用静态字面量、局部聚合以及已证明的直接入口。普通分配、递归、异常观察和真实挂起仍使用统一的可恢复帧；本轮不引入另一套通用 shadow/continuation 表示。主要帧来源处于会分配或修改对象的递归函数，入口重试会重复效果；持久恢复状态因而不能仅凭“当前无 GC 根”而删除。两个较小、可完整比较的帧成本实验已经出现稳定退化，缺乏依据继续扩大这次重写。

X05 保留已验收的帧位图、归属复用、宿主查询消除和静态字面量直接入口；撤下两份帧复用候选。后续重新研究生成代码内分配时，需要先给出包含递归和高频 GC 的端到端改善，明确缓存命中条件与页保留上限，再推进到 ABI 变化。

S02 采用局部唤醒的临时分配消除，保留现有 FIFO、调度 quantum 和每片段服务边界。镜像生命周期候选已按独立退化证据撤回；本轮不引入优先接收方交接或第二套短任务调度循环。当前方案已经在保持调度回合数不变的条件下消除大量确定性工作，先由完整产品测量验收这一收益。

这些决策保留明确的重启条件：优化后的 profile 仍显示相应边界主导耗时；新设计在副作用前完成可失败准入；有唯一的根、源位置和恢复表示；实际公平性、取消及宿主进展测试通过；完整冷/热目录没有重复确认的不可接受代价。该条件用于后续负载驱动的工作，不作为当前计划中持续滚动的待办。
