## 后续处理

Core 整数查询优先修复，同时验证 Map 删除重插和浮点键的既有收益。整数索引候选保持原有表布局、实际扩容路径和 host ABI；完整语言、宿主、分布与端到端测量通过后再选择源码。

no_std 三版定位使用完全相同的当前 VOB。融合前后两份冻结源码仅 VM 分派与其测试不同。该对照用于区分撤回已拒绝融合方案的局部收益与当前组合的新增代价，结果尚待测量。

Native 宽参数路径继续保留真实回退记录；参数发布量减少不能替代端到端结论。Rust 普通整数和字符串 hash 未在最后组合中改变，字符串回退不能直接归因于浮点/复合键的 hash 修复。

两组编译成本各九种场景均未出现墙钟或 CPU 区间全正的回退，因此未追加第三轮编译测量。全量编译对照与资源变化见[主报告](toolchain-final-performance-report-20260912.md)。
