# Map hash 分布修复：完整工作量对照 · 2026-09-12

浮点及部分复合键的低位分布会退化到近似线性扫描。采用完整语义 hash 后的有界两次乘法混合；Rust 普通整数和字符串继续使用已有路径，Core 对非字符串结果先做完整 64 位混合再取桶索引。float32 只使用有效低 32 位；带符号零、NaN、组合键及类型身份的相等契约保持不变。

在容量 1,024、768 个连续分数键时，Rust float32/float64 平均命中探测由 369.07/368.28 次降至 2.37/2.50；Core 由 384.50 次降至 2.20/2.26。部分原来恰好低碰撞的序列会增加探测：Rust 连续 interface-int 由 1.08 增至 2.48，但相同类型 stride=1024 的命中由 369.05 降至 2.03。完整负载的耗时和这部分代价仍由最终性能矩阵验收。

Rust 两版各三个独立进程、各 1,290,240 次真实公开查询，输出、校验和、查询数相同，同版三次全部诊断相同；查询窗口内分配与释放均为零。桶探测从实际生产 hash 和桶控制区重建，重建工作在分配计数窗口外。Core 实际执行生成的查询函数，五类语义检查通过，诊断阶段宿主调用为零。

扩展 ABI v10 的指纹包含 key hash 方案，避免旧扩展用旧算法访问新表。Core 的生成代码构建身份参与缓存键；该算法调整保持 host ABI9。
