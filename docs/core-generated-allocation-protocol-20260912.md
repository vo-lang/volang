# Core Wasm 生成分配与帧状态协议草案 · 2026-09-12

状态：设计中，尚未实现或通过性能验收。本文记录 X04/X05 的实现约束和实验顺序，不能作为工作包关闭证据。

## 当前瓶颈与约束

已保存的 binary-trees 工作量包含约 644 万次对象分配、649 万次帧建立/释放和 1,184 万次屏障调用；历史总内存宿主调用约 3,132 万次。这些数值归属原诊断快照，后续原型必须重新计数。最近的局部聚合和静态字面量降低已消除其选定负载中的子帧；递归分配路径仍保留持久帧。

`AotHeapSpan` 的分配位图、请求范围、身份、年龄、帧位图和函数身份现在存放在 JavaScript 数组中。`AotMemoryRuntime.allocate` 负责准入、collector 工作容量、屏障提示、发布、分配总量和债务。生成代码调用宿主后才能得到新的对象身份。将空闲地址交给生成代码、稍后再补记账，会破坏分配可观察性和有界 GC 的前提。

`function_capabilities` 把可能分配传播为可能挂起，`materialized_functions` 因而保留这些函数的持久状态。删除这条传播会丢失 GC 让出时的局部变量。旧的不可达 rooted adapter 已清理；重新引入直接入口需要一套完整的根与恢复协议。

## 一个权威状态，两个执行者

第一份实验应先统一可被生成代码访问的分配元数据，保持现有函数帧策略。每个 span 的对象身份、精确请求范围和 allocation/young/frame 位图只有一份存储。JavaScript collector 和生成代码访问该存储；宿主的目录、容量列表和政策对象保留独立职责。

候选存储位置是专用线性内存元数据区。该区域不发布为 managed span，也不能通过 managed 指针验证。预留和增长必须单独计入宿主元数据与 Wasm 页数，managed hard limit 仍只限制托管容量。导出描述符只包含经过宿主认证的偏移、容量和代际；不得依赖 guest 对象头建立自身身份。元数据增长后，所有宿主视图必须刷新。此选择需要 Core 宿主 ABI 和缓存身份同步升级，并验证真实浏览器；当前 ABI9 产物保留独立对照。

生成代码的许可限定为一个 Island、一个已准入 span、一个大小类别和一个精确布局。许可消耗顺序为：检查容量和 GC 边界，领取未使用单元，提交位图及身份，初始化对象头与数据，更新 requested/live/object-count/allocation-total/debt，最后发布结果。新对象的 collector 颜色必须与宿主路径一致。失败发生后不得继续 guest 效果。

collector 步骤、Island 切换、普通宿主分配、禁分配和政策改变必须先撤销许可，归还未消费的容量。未消费单元计入容量预留，不计入已发生分配；全部许可共享 maxObjects 和 collector 工作容量预算。第一份实验只支持常量布局小对象；大对象、动态布局、端点和宿主调用继续使用现有路径。

## 帧状态分离的后续步骤

GC 根记录只需描述存活引用及条件接口对；逻辑调用记录需要函数、调用点和父链；可恢复状态需要恢复 PC、活跃槽、defer/panic、预算和等待登记。三者生命周期不同，应在接口中显式区分。

在准确 root publication 和挂起物化实现前，分配函数继续保留当前持久帧。直接入口原型需要在普通返回、GC 让出、燃料耗尽、真实等待和异常传播五类出口分别验证：普通返回可以释放临时状态；其余出口先保存准确 live-in，再退出 Wasm 调用栈。任何 native stack 地址都不能保留到宿主调度器。物化所需容量必须有明确准入与失败顺序。

另一候选是每 Fiber 的有界帧块：多数建立/释放在已准入块中推进，块边界才进入宿主。子帧不能冒充独立 managed 对象；根枚举、函数身份、过期帧、宿主保留调用和清理必须使用经过认证的帧块记录。单纯把子帧指针改成块内地址会使现有 `frameFunction`、租约身份和渐进扫描失效，不能作为局部补丁交付。

## 实验与验收顺序

1. 从冻结产品记录对象/帧/宿主调用和 JS 元数据字节，建立相同 VOB 的对照。
2. 先验证元数据存储迁移，保持生成代码走宿主；对象身份、精确范围、所有 GC 阶段及错误注入结果必须一致。单独测宿主访问代价。
3. 增加小对象许可的生成消费；逐次比较准入、记账与工作量，覆盖混合布局、容量边界、饱和代际、禁增长、OOM、Island 切换和跨步扫描。
4. 生成路径有收益且普通负载无明确回退后，再实施帧根与恢复接口。递归、宽聚合、接口、内指针、panic/defer、异步宿主和取消均需实际生成代码覆盖。
5. 分别报告冷执行、模块复用执行、宿主调用、managed committed/live、元数据、代码体积、编译代价和响应性。完成真实浏览器及第二原生架构相关检查后再决定工作包出口。

普通 fast-path 的收益不能抵消遗漏的状态协议。实验若无法在现有可观察内存契约内带来稳定收益，保留完整负结果并终止该方案；当前尚未取得这样的否定证据。
