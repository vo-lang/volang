# Caller 精确源位置修复 · 2026-09-12

已保留修复：同一字节码PC对应多条调试位置时，VM的`runtime.Caller`返回最后一条精确匹配。代码整理删除指令后，多个旧位置可以合并到一个PC；公共验证器允许这种有序重复，PC重映射保留稳定顺序，公共调试查询与Core Wasm也都采用末项。原VM提供者选首项，可能返回已移除代码的文件和行号。

改动仅涉及`vo-vm/src/runtime_externs.rs`。查询仍只接受精确PC，缺失位置返回失败；不会借用上一条位置。复杂度仍为二分查询，无ABI或字节码格式变化。完整逻辑内联栈仍属G02/C07后续工作。

新旧版本使用相同VOB。前六个运行时后端在重复位置中分别返回首项`removed.vo:23`与末项`caller-leaf.vo:777`/`caller-outer.vo:888`；错误末项反向控制确认实际遵循元数据顺序。Core原本正确，两版生成镜像完全一致。JIT/OSR均有实际生成代码入口；Native AOT的运行期函数/循环编译及编译耗时始终为零。

本次通过数为73次产品级检查，另有12项提供者检查。未重跑全部语言目录，也没有把父产品的8,293项重复计入。本次修复不声明新的性能百分比。
