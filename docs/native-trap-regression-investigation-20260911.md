# 原生组合回退调查：保留证据与撤回实验

两项ABI实验均未收回主要回退，已经撤回；当前live产品恢复为通过正确性检查的C07/ABI12，源码在此基础上继续推进X02入口效果证明。原始产品、失败、测量和机器码仍在证据目录。完整组合的性能验收继续开放。

## 已确认的范围

38项七后端全目录完成6,384次执行后，对全部七个回退初筛项目独立复测20对样本，共308次执行。全部输出正确，quicksort JIT/OSR仍慢9.26%/10.00%；四项Native AOT仍有回退。jit-copy VM的初筛回退没有复现。逐项区间见[组合报告](combined-toolchain-benchmark-report-20260911.md)。

进一步的四版本、两种启动放置、六组配置共672次执行全部正确。版本依次为C08、heap候选、修正版ABI12、C07；物理APFS副本与符号链接的参数长度相同，统一执行相同候选VOB。两种放置均保留quicksort约9%–10%的回退，后面三个版本的均值接近。

三项负载在JIT/OSR中的24次机器码诊断表明，heap候选→修正版ABI12→C07的IR/VCode文本均相同。quicksort独立计数中的入口、退出、GC工作相同，编译时间约11ms；新增机器码为27,012→27,148字节。诊断打印会增加编译时间，所以机器码转储过程的耗时只用于诊断。

ABI13将新增的逻辑来源字段移至JitContext尾部，恢复热字段的原偏移并消除中部填充。它没有解释主要回退。ABI14进一步把异常种类和完整32位物理PC合并为一个64位参数，逻辑来源独立保留，减少冷出口参数。它通过268项JIT单元测试，但quicksort相对C08仍慢8.78%/8.62%，Native AOT回退也没有收敛，并出现新的VM产品回退，因此未保留。

VM执行不会调用原生异常helper。上述VM差异按完整二进制差异记录，不能归因为执行了紧凑异常传参；代码/数据放置等具体因素还需要隔离。也不能从这两个实验推导“异常来源必然无性能成本”：紧凑编码同时改变了常量形状和生成代码布局，并未重现旧版本的全部机器码。

## 验证过程中的失败

ABI13首次准备驱动遗漏了诊断环境参数，没有输出AOT统计，且未应用指定OSR阈值。该准备目录与脚本原件保留；修正驱动后重新执行全部36次预检，正式计时只使用修正后的身份。

ABI14测试编译期间，1,540份Rust编译线程采样均停在加载proc-macro动态库的`dlopen → dyld mapSegments → __fcntl`。测试二进制首次启动也有等待，但没有取得该次等待的堆栈，不据此混同原因。首次启动等待结束后保留SIGTERM退出记录，同一SHA二进制复跑取得267通过、1失败；失败来自新增夹具没有入口函数，被公共验证器正确拒绝。补齐零槽Return入口后完整268项通过。所有失败源码、二进制身份、日志及后续修正均保留，构建/等待/采样时间未计入性能。
