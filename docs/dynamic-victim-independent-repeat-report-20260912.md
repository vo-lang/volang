# 动态调用缓存独立复测 · 2026-09-12

后期出现新目标的闭包与接口负载，在使用动态调用缓存的六个后端上继续获得稳定收益：闭包耗时下降6.4%–18.0%，接口下降12.7%–17.6%。Core Wasm 对照差异的区间跨零。首轮 float32-vector/OSR 与 string-constants/JIT 的较大差距未重现；若干约0.4%–1.4%的代价仍有独立复现，尚未确定共同根因。

本次保留首轮所有正置信区间、超过3%的不确定差异，以及两个后期目标负载在全部七个后端的结果，共56组。每组2对预热、24对交替正式样本，共2,912次执行、2,688次正式样本，输出全部正确。使用冻结产品，计时期间无构建、功能测试或profile。

逐组95%配对区间中，耗时全正有9组，CPU时间全正有11组。完整结果如下；这些负载经过有意筛选，不计算全目录平均值，也不把增量结果加到累计收益。多重比较下的单行区间用于筛查，跨独立运行复现的项目继续跟踪。

缓存从四个稳定目标扩展为四个稳定目标加一个可替换目标，每个调用点由160字节增至200字节。这个空间变化已确认；它与各项算术、容器或调度耗时变化之间的因果关系仍需实测。
