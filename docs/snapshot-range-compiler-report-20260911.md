## 改动与正确性边界

SnapshotFs 继续用已有的 BTreeMap 保存文件。目录查询从按路径分量排序的下界开始，只遍历该目录的后代；相邻后代共享的直接子目录只建立一次输出路径。exists/is_dir/entry_kind 通过首个后代判断，无需扫描整个文件集合。没有增加常驻索引。

范围边界利用 Path 的分量排序，实际 Rust 实现见 [标准库 Path::cmp](https://doc.rust-lang.org/src/std/path.rs.html#3862)。最终输出仍执行原有规范排序。新增测试覆盖相近名称、相对/绝对路径、点和父目录归一化、文件与目录冲突、替换、Unicode、Unix 非 UTF-8 名称、目录项上限，以及生成的 97 包 × 17 文件与旧全扫描语义的逐项对照。

首轮 Engine 204 项通过、2 项创建非 UTF-8 临时路径受沙箱限制的失败记录保留；同源允许该本地操作后 206 项通过。未改变文件系统读取权限、快照一致性扫描、模块身份、缓存版本或字节码格式。

## C11 包级增量决策

本轮维持整次编译内容缓存和会话内包缓存，不引入跨编译会话的包级分析缓存。最新大工程变更场景中，解析约 7.07 ms、类型检查 15.39 ms、codegen 28.44 ms，三者合计约 50.90 ms，占 281.36 ms 总阶段中位值约 18.1%。输入捕获、指纹、真实上下文和快照上下文合计约 166.66 ms，约 59.2%；验证约 30.53 ms，缓存发布约 28.34 ms。各阶段单独取中位数，因此比例仅用于定位。

重复分析尚未成为当前代表工程的主导成本，达不到计划规定的包级增量实施条件。跨会话复用还必须处理依赖/配置/源代次及 TypeKey/ObjKey/ExprId 的 arena 所有权；现有缓存命中已经跳过解析、类型检查和 codegen。该结论属于本次 2/9/33 包矩阵，未来更大的真实工程若呈现分析主导，需要重新测量与决策。C11 的阶段诊断、当前选定优化及本轮条件决策完成；全工具链最终累计验收继续归属总计划。
