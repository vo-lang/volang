# 反馈驱动标量内联：集成验收 · 2026-09-12

当前源码已接入 Island 本地动态调用反馈，在优化层对稳定标量目标生成带守卫的完整内联。目标身份、入口代际、隐藏参数形状及剩余预算均继续验证；变化目标和低预算进入原有通用路径。静态和反馈内联共享 256 单位复制预算，每个产物最多 16 个反馈调用点。

真实集成测试发现两个验收与实现问题，现均已修复：

- 原测试比较 VM → JIT 入口次数，遗漏了原生函数之间的调用。现在读取已有的逐函数训练计数，不在执行热路径加入新计数。32 次仅调用者预热使调用者先升层；测试同时证明被调用者始终留在可计数的 baseline 训练窗口，避免把升层停止计数误判为内联收益。
- 小函数配方遗漏 `CopyN`，实际标量接口包装器因此无法内联。共享配方现验证完整范围及逐槽类型，先读取全部源值再更新目标，保留双向重叠语义；宽复制计入编译复制预算。普通整数、浮点、相同区域和双向重叠均通过实际原生入口测试，错误范围和不相容类型拒绝准入。

三个 Engine 程序覆盖闭包目标、标量接口接收者及双返回值；分别执行 baseline/optimizing 与普通函数/混合 OSR 四种配置，穿插显式 GC。在每个 10,000 次调用程序中，优化后至少消除 2,000 次实际原生 callee 入口，目标切换后约 1,000 次第二目标调用仍发生，输出相同。更低层测试继续覆盖 0–6 预算、目标和代际失效、宽参数、浮点及返回窗口。

同时删除只服务旧测试的重复升层包装方法，生产路径与测试共用含反馈的单一入口。Native 执行 ABI 保持 15；配方与反馈只影响编译器分析及生成代码，compiler-free 运行库检查通过。

上述证据确认正确性与调用消除。完整产品、编译成本、代码体积和端到端性能仍由最终组合验收给出，不将入口减少直接换算为耗时提速。
