## 执行资源方案的边界

当前每个Island在自己的执行线程上建立独立VM和堆。命令处理与guest执行分别有预算；活跃等待和完全空闲分别以10ms/100ms检查中断与事件。直接去掉等待轮询会影响只有AtomicBool的取消路径，需要配套唤醒协议。

通用工作线程池仍处于设计阶段。它需要明确单Island单执行者、线程亲和/TLS、阻塞外调和回调，以及取消/退出期间VM与transport的所有权。初步方向是保持当前CPU路径，单独实验支持合作式让出的短任务/空闲资源复用；受限池中若一个外调长期占住线程，其他Island的进展必须有规则。当前没有实现线程池，也没有将S03标为完成。
