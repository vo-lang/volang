## 结论

当前最值得投入的方向是让一次 UI 变化只承担相应的工作：限制组件失效范围、避免只读拓扑查询复制整棵祖先的子列表、按提交影响更新宿主控件，以及为文档和数值数据提供增量传输。它们同时改善 VM 与 AOT，也覆盖表单、编辑器、图表、路由和面板布局。

目前的证据足以确认多处额外工作，但不足以承诺所有场景接近手写 JavaScript，或给出整体提速倍数。现有正式交互性能主要覆盖列表五项和 Studio 三项；输入法、长文档、复杂表单、持续滚动、混合负载和长期内存仍缺对应性能基线。

本报告列出 16 组问题与缺口。工作量探针验证了其中 7 种行为；其余按源码事实或待测风险分别标注。性能成本与功能错误分开处理：本轮探针均检查输出正确，没有据此声称发现新的功能错误。

证据等级：**W** 表示本轮运行当前实现并计数；**S** 表示当前源码可直接确认的机制；**H** 表示需要浏览器或实机测量才能判定影响。历史计时单独标注日期和产物。

## 本轮复现

宿主探针直接执行当前生产 `prepareBatch`、`WidgetHost`、`InputQueue`，使用模拟节点元数据隔离算法，检查原树未被修改和准备后的顺序正确。Vo 探针通过已有 release CLI 编译当前 UI 源码，在原生 VM 上执行公开 Root/State/Form API。

| 操作 | 本轮结果 | 含义 |
| --- | --- | --- |
| 父组件更新，100 个子组件的输入均未变 | 100 个子组件全部重渲染 | 父级更新不能自动跳过未变的子组件 |
| Derived 的输入保持不变，所属组件另一状态更新 | Derived 重新计算 1 次 | 缓存跨所属组件的重新声明失效 |
| 100 字段表单修改一个字段 | 100 个字段重渲染，调用完整验证器 1 次 | 字段读取缺少独立失效边界 |
| 100 / 1,000 / 10,000 个兄弟节点下修改一个叶子文本 | 分别复制 102 / 1,002 / 10,002 个 children 项，均只准备 4 个 shape | 只读祖先查询也触发宽数组复制 |
| 合法的反转指令流，100 / 1,000 / 10,000 个兄弟节点 | 线性查找逻辑比较数 5,050 / 500,500 / 50,005,000 | 多次 `indexOf` 累积为二次复杂度 |
| 无 widget 值变化，1 / 100 / 1,000 个 widget 执行提交回调阶段 | 分别调用 1 / 100 / 1,000 个 `afterCommit` | 检查范围取决于存活 widget 数 |
| 同一 posted task 前排入 1 / 100 / 1,000 个 pointermove | 分别在一个 batch 交付全部事件；1,000 个为 114,009 字节 | 队列按大小限额组织，未按事件语义合并或按时间预算分批 |

“逻辑比较数”按稠密数组找到目标需要经过的元素计数；同时记录的“逻辑移动项”按 splice 的索引位移计算。它们均不等于实际 CPU 指令、物理复制字节或浏览器耗时。反转探针是一组合法协议输入，不声称与正式列表页面的完整 mutation 流逐条相同。原生 VM 的计数也不换算成 Wasm 延迟。

## 逐项问题与改进方案

### 01. 组件更新缺少稳定输入边界 — P1，W/S

`reconcile.vo` 在更新组件时重新执行其 render。父组件生成新的 View 与捕获闭包后，即使各子组件的业务输入未变，也会继续递归渲染。Scope 的响应式订阅能缩小直接状态写入的影响；父级协调仍会扩大工作范围。探针已复现 100 个未变子组件全部执行。

影响主题、布局外壳、路由、表单、仪表盘和动态组件树。建议提供可表达稳定输入/版本的组件契约，先让组件库内部能安全跳过未变子树，再考虑编译期证明。跳过必须同时处理上下文依赖和子组件自身的 dirty 状态。

不能以闭包地址或 Type/key 相同推断输入相同：捕获的普通 props、事件处理器、错误边界与 effect 都可能变化。验收需覆盖这些语义，以及局部叶子更新、父级无关更新和上下文更新三种工作量。

源码：[reconcile.vo](../ui/next/reconcile.vo)、[root.vo](../ui/next/root.vo)、[view.vo](../ui/next/view.vo)。

### 02. Derived 跨声明失效与依赖簿记成本 — P1，W/S

`Derived` 每次重新声明都会刷新 compute 捕获并 invalidate；所属组件无关状态更新也会导致重算。观察者每轮 detach 后重新建立订阅。现有行为保证普通捕获保持新鲜，但限制了昂贵过滤、聚合、验证结果的缓存收益。

建议补充明确依赖或稳定版本的派生计算契约；只有输入契约允许时才跳过计算。结果相等抑制传播需结合订阅调度验证，不能简单在当前 invalidate 上补比较。先测计算次数与订阅规模，再决定是否值得引入依赖版本标记；避免为了几条依赖维护复杂增量容器。

源码：[derived.vo](../ui/next/derived.vo)、[state.vo](../ui/next/state.vo)。

### 03. View 构造与静态内容重复准备 — P1，S

`Element`/`Fragment` 复制 children，属性 builder 逐次构造描述；每轮 render 重新创建许多描述、闭包和临时集合。语义文档 `Decode` 验证一次，`document.View` 又验证并遍历全树、排序属性，重新生成 View。当前 Document 可由应用构造或修改，直接删去再次验证会改变契约。

建议先定义不可变、已验证的静态内容句柄以及稳定子树复用规则，把校验、属性整理和静态描述创建移到内容版本变化时。动态文本/属性建立明确的绑定槽，保持同一套组件生命周期、错误处理和提交协议。编译器自动提取静态内容可作为后续增强，前期先通过小型公开/内部 API 验证收益。

避免另外维护一套“快速 UI”生命周期。SSR、普通挂载和动态降级路径必须共享语义。Vue 的静态缓存、patch flags 与动态后代索引，以及 Solid 的细粒度订阅，为这类方向提供成熟参照；具体 Vo 收益仍待测。[Vue 渲染机制](https://vuejs.org/guide/extras/rendering-mechanism)、[Solid 响应式机制](https://docs.solidjs.com/advanced-concepts/fine-grained-reactivity)。

源码：[view.vo](../ui/next/view.vo)、[document.vo](../ui/next/document/document.vo)。

### 04. 拓扑只读查询复制宽 children 数组 — P1，W/S

`topology.ts` 的 `shape()` 将节点放入事务 overlay 时直接 `children.slice()`；命名空间检查递归访问祖先也走此路径。因此叶子文本修改可以复制与本次更新无关的大量兄弟项。探针宽度扩大 100 倍，对应复制项近似扩大 100 倍。

建议将只读节点事实与可写拓扑分离，只在真实改变某个父级 children 时取得可写副本。需要保持一整批校验失败时不改变 live tree、批次内移动后的 namespace 判断、hydration 和 portal 的正确性。这个改动较局部，适合作为第一批优化。

源码：[topology.ts](../lang/crates/vo-web/js/ui_next/topology.ts)。

### 05. 批量兄弟移动的宿主预检查为二次复杂度 — P1，W/S

移除和插入反复对同一个 children 数组 `indexOf`、`splice`。Vo 侧已有 LIS 顺序优化，减少循环平移等操作的移动数；宿主仍独立承担对收到的操作做结构校验的成本。完整反转和混合大批次仍触发多次长数组搜索与位移。

建议按被修改的父节点建立临时顺序结构，批次内增删移动在该结构上完成，结束后一次物化。可以试验临时前后链接/索引，避免为每个只读文本更新常驻另一套全局索引。必须覆盖批次中间状态、跨父级移动、before 目标、销毁、portal 和原子拒绝；按大小梯度验证复杂度与小批次常数成本。

源码：[topology.ts](../lang/crates/vo-web/js/ui_next/topology.ts)；已完成的优化：[LIS 对照](../ui/next/keyed-order-performance.md)。

### 06. 表单按整份快照失效和验证 — P1，W/S

所有字段值、错误与 touched 的读取最终订阅同一个 Store。`ChangeAll` 复制 values map，并通过 `check` 将完整 Data 副本交给完整 Validate。`Use` 还会重建字段列表、默认排序与声明检查。100 字段探针只改一项，100 个字段全部重新渲染。

建议内部按字段维护 value/error/touched 的信号或等价选择器；聚合 dirty/valid/submitting 使用独立版本与计数。声明准备在字段集合变化时执行。提供局部验证器及显式跨字段依赖；已有全表验证器继续按原契约运行，提交阶段仍生成一致的冻结快照。字段数组需以稳定路径维护顺序与状态，取消和过期异步结果规则保持统一。

验收 10/100/1,000 个字段、单字段输入、跨字段校验、条件字段和数组增删。目标是普通单字段操作的渲染范围随真正依赖数量增长；全表验证本身的业务成本单独计量。

源码：[form.vo](../ui/next/forms/form.vo)、[data.vo](../ui/next/forms/data.vo)。

### 07. 事件批次与 UI 调度缺少交互预算 — P1，W/S/H

InputQueue 是有界 FIFO；完整 posted task 后交付，正确保留原生默认动作时序。一个 batch 可含大量连续事件，Vo host 先 Dispatch 完整批次，再 Flush 全部 dirty scopes。持续 pointermove、任务完成和普通输入可能竞争同一条队列。探针确认 1,000 个 move 可一次交付，实际积压延迟待测。

Web VM 驱动在 exchange 之间同步调用 `run`/`runScheduled`，入口没有浏览器时间片预算；AOT 已有有界运行量与每 16 个 guest quantum 的宿主让出，不能把两者都描述为完全没有调度。执行器让出与 UI 提交可见性仍是两件事：未完成的渲染事务不会因此提前显示。

建议先统计事件排队、处理与提交耗时，增加完整事务之间的调度机会。对拖拽位置、尺寸等状态型订阅显式提供 latest-value 语义；绘图笔迹、点击、键盘、IME、命令结果保留必要事件。需要时再增加可推迟更新的 API，保留紧急输入和取消处理。

已有 Worker bridge 可用来隔离大任务；默认 mount 仍在主线程执行。Worker 需要额外复制、往返与就绪成本，应按交互矩阵选用，不能视为减少计算总量的保证。

源码：[input.ts](../lang/crates/vo-web/js/ui_next/input.ts)、[host.vo](../ui/next/host/host.vo)、[root.vo](../ui/next/root.vo)、[vm.ts](../lang/crates/vo-web/js/ui_next/vm.ts)、[aot_scheduler.ts](../lang/crates/vo-web/js/aot_scheduler.ts)、[worker-host.ts](../lang/crates/vo-web/js/ui_next/worker-host.ts)。

### 08. 每次提交遍历全部 widget — P1，W/S

Renderer 每次提交调用 WidgetHost.afterCommit；它遍历全部存活 binding。编辑器回调会重新检查控件身份、disabled、标签、配置等。即使一个 widget 的 value 未变化，仍有检查成本。探针确认回调数与全部 widget 数一致。

建议生成提交影响集合，将直接属性变化、相关祖先变化、控件/标签关系变化分别传给需要检查的 widget。保留初次挂载、懒加载完成和外部平台事件的显式同步。单纯按 widget payload 是否变化跳过会漏掉 fieldset disabled、标签和焦点投影等依赖。

源码：[widgets.ts](../lang/crates/vo-web/js/ui_next/widgets.ts)、[renderer.ts](../lang/crates/vo-web/js/ui_next/renderer.ts)、[editor.js](../lang/crates/vo-web/js/ui_next/editor.js)。

### 09. Popover 全量布局检查与读写交错 — P1，S/H

每次 settle 遍历所有打开的 popover，检查可见性、读 anchor/popup 几何并定位；position 中存在样式写入后读取布局，sync 重新整理观察对象。源码确认工作存在，强制布局次数和实际占比需浏览器 trace。

建议按尺寸、滚动、相关提交与外部布局变化标记需要重新定位的项；同一帧集中处理准备、几何读取和写入，尽量保留观察关系。已有 resize/scroll 的 rAF 合并应保留。字体加载、视觉视口、祖先移动、RTL、过渡退出、隐藏锚点和焦点恢复都需纳入正确性验证。

源码：[popovers.ts](../lang/crates/vo-web/js/ui_next/popovers.ts)、[motion.ts](../lang/crates/vo-web/js/ui_next/motion.ts)。

### 10. 编辑器每次编辑投影全文 — P1，S

编辑器 publish 调用 `doc.toString()`，将全文赋给投影 textarea，发出 input。通用输入路径随后传递控件字符串值。CodeMirror 的内部增量文档与视口渲染，无法消除这条桥接路径的全文成本。当前显示上限为 100 万字符，长文档场景需要独立测量。

建议增加带文档版本的编辑增量通道，打开/重同步/提交/保存时取得完整快照，正常编辑发送变化范围与选择。需要同时重设计投影 textarea 的快照时机，否则仅减少 wire 传输仍保留全文复制。原生表单提交、reset、无增强降级、辅助技术、IME、撤销与外部替换的行为必须一致。

浏览器侧编辑显示应能使用控件已有的局部更新；Vo 接收业务编辑状态和必要快照。先解决公开文档模型及契约，再接补全/诊断服务的版本与取消，避免多套互不一致的全文缓存。

源码：[editor.js](../lang/crates/vo-web/js/ui_next/editor.js)、[editor-provider.ts](../lang/crates/vo-web/js/ui_next/editor-provider.ts)、[renderer.ts](../lang/crates/vo-web/js/ui_next/renderer.ts)。

### 11. 图表与位图仍使用大字符串快照 — P1，S

`plot.Chart` 每次声明都 JSON 编码全部 X/Y；游标更新引起父级重渲染时，即便数据不变也承担编码成本。宿主按变化值 parse 并 setData。位图在 NewBitmap 时将 RGBA 编为 Base64/JSON，宿主经历字符串解码、数组转换、ImageData 和整幅写入。位图对象已缓存 payload，复用同一 Bitmap 时不能重复计算初次编码成本。

建议统一提供有界、带版本和所有权的数据附件机制，先覆盖图表数值数组与位图。数据版本与尺寸/主题/游标等视图状态分离；按实际需求提供追加/范围替换、像素区域更新。连续动画优先使用浏览器帧调度和控件能力，Vo 提交业务参数、数据与控制事件。

相同 uPlot/CodeMirror 实例作为裸宿主参照，有助于测出 Vo 包装增加的开销。图表抽样属于可选择的数据展示策略，需要单独验证保真与可访问替代表达。

源码：[plot.vo](../ui/next/web/plot/plot.vo)、[uplot.js](../lang/crates/vo-web/js/ui_next/uplot.js)、[canvas.vo](../ui/next/web/canvas/canvas.vo)、[canvas-bitmap.ts](../lang/crates/vo-web/js/ui_next/canvas-bitmap.ts)。

### 12. 集合工具与尺寸观察尚未统一到规模化路径 — P2，S/H

已有固定/可变高度虚拟窗口、稳定 key、缓存 Items 和 Fenwick 高度索引，这是可保留的基础。剩余成本包括每个尺寸订阅自己的 ResizeObserver/rAF、行宽变化时重建高度模型，以及测量/视口观察维护书签与状态。kit 的 Combobox 会重新复制、筛选选项；Table 按传入行逐行构建，分页和虚拟化由调用者选择。

建议优先复用 Items 和窗口模型，让常用控件可以组合相同的数据版本/可见范围接口。尺寸观察按根共享或批量交付；一次宽度世代变化只重建一次模型，严格处理过期尺寸和滚动锚点。不能假设所有观测的行宽完全相同，也不能直接用全局最新尺寸覆盖不同节点。

树组件应按可见展开序列组织，随后复用窗口模型；目前缺树交互的正式性能样例。Table 维持简单语义表格路径，额外提供可选大数据方案即可。先验证 1,000/10,000/100,000 项，避免给小集合强加重型索引。

源码：[variable.vo](../ui/next/collection/variable.vo)、[height_index.vo](../ui/next/collection/height_index.vo)、[items.vo](../ui/next/collection/items.vo)、[size.ts](../lang/crates/vo-web/js/ui_next/size.ts)、[combobox.vo](../ui/next/kit/combobox.vo)、[table.vo](../ui/next/kit/table.vo)。

### 13. 启动加载串行，hydration 仍执行完整首次构建 — P1/P2，S/H

mountUi 等 artifact 下载为 ArrayBuffer 后才开始 loadVm/初始化，或动态加载 AOT 入口。SSR 提前提供可读内容并接管早期输入，但宿主仍采用整根树、guest 仍生成完整初始描述与提交。长静态文档和大页面的 hydration 成本需要独立测量。

第一步并行启动独立资源加载，保持关闭/失败时的生命周期，并利用已有按 initializer 身份去重的 VM 初始化。后续才评估支持流式编译的入口，保留 metadata/ABI 验证。已有分页面入口、可选 editor/compiler 懒加载和精简运行时应继续保留。

结构层面与第 03 项共同处理静态内容的预编译、描述复用与交互边界。选择性 hydration/多岛只有在保持上下文、事件顺序、服务所有权及早期输入的条件下才值得加入。导航需分别测冷进入、缓存命中、返回恢复和快速取消；缓存不应重复保留整个已离开的执行根。

源码：[mount.ts](../lang/crates/vo-web/js/ui_next/mount.ts)、[hydrate.ts](../lang/crates/vo-web/js/ui_next/hydrate.ts)、[navigation.vo](../ui/next/navigation/navigation.vo)。

### 14. Wasm AOT 的调用帧、分配与 GC 放大 UI 临时工作 — P1 诊断/P2 重构，S/H

当前分析将 may_allocate 纳入 may_suspend，并向调用者传播；可分配函数保留能够暂停恢复的 durable 状态。宿主 JS 参与托管堆、对象登记和 GC。频繁分配的 render、表单、字符串处理与协议生成会共同支付这些成本，AOT 的编译产物因此没有自动获得低分配、低调度成本。

现有运行时已经区分 suspension/allocation/unwind/host effects，也有直接调用和局部 ABI 路径。后续工作应利用现有分析，研究在限定安全点区间分离 GC 根、逻辑调用栈与真正需要恢复的 continuation；不能直接把所有可分配函数标成不可挂起。

先测第 01–13 项减少工作后，各 UI 场景的帧分配、GC 扫描、guest CPU、宿主调用占比。仍为主因时再做一个受限原型，验证精确根、panic/recover、递归、取消、内存限额与调度。GC 迁入 Wasm、帧池或默认 Worker 都需要独立比较；当前证据不足以承诺这些改动的净收益。

原生桌面 VM/JIT/native AOT 使用不同执行链，不能直接套用 Core Wasm AOT 结论。先共享 UI 层工作量优化，再测各自后端剩余成本。

源码：[analysis.rs](../lang/crates/vo-wasm-aot/src/codegen/analysis.rs)、[mod.rs](../lang/crates/vo-wasm-aot/src/codegen/mod.rs)、[aot_memory.ts](../lang/crates/vo-web/js/aot_memory.ts)、[aot_collector.ts](../lang/crates/vo-web/js/aot_collector.ts)。

### 15. 异步突发、长期生命周期与空闲资源缺性能证据 — P1 验收，S/H

请求缓存已有去重、容量限制、作用域取消和初始数据复用。任务完成、watch 更新仍通过统一输入通道交付；大响应解码和同时完成的请求可能造成更新突发。是否导致明显交互回退，需要输入与异步任务并发的样例。

应记录请求排队、解码、失效扇出和提交，状态订阅仅在明确允许时合并；命令结果不得静默丢弃。文件读取/预览另测字节复制、取消和实际内存峰值，保留已有大小边界。

卸载和取消正确性测试无法代替长期资源曲线。增加反复导航、开关 editor/plot/dialog、失败重试和空闲观测，分别记录 guest live/committed、JS heap、DOM/observer/listener/task 数及空闲唤醒。Wasm committed 高水位与真实存活内存分开解释；生产交互计时前不强制 GC。当前没有足够证据声称存在泄漏，也没有足够证据宣称长期占用已经稳定。

源码：[data/client.vo](../ui/next/data/client.vo)、[query.vo](../ui/next/data/query.vo)、[resource.vo](../ui/next/resource.vo)、[tasks.ts](../lang/crates/vo-web/js/ui_next/tasks.ts)、[http.ts](../lang/crates/vo-web/js/ui_next/http.ts)。

### 16. 验收指标集中于少数离散交互 — P1，已确认覆盖缺口

缺少统一的全场景规模梯度、持续交互、混合负载和资源生命周期报告。小列表耗时、源码静态审查和功能测试各有价值，单独使用均无法验证全范围体验。

需要建立以下矩阵。优先制作独立框架样例与相同功能的参照，Studio 只保留少量组合展示，避免把展示产品扩展成复杂业务系统。

测量要求：

1. 使用同 DOM/数据/控件行为的 Vue/Svelte 或裸 DOM 对照；编辑器/图表另以相同第三方库直接使用为参照。记录生产产物、工具链、依赖和源码身份。

5. 对稳定、足够耗时的案例建立每场景相对回退门槛；亚毫秒案例使用绝对误差预算。大型重建同时报告总完成时间与等待期间的输入响应。
6. Headless 可覆盖正确性、DOM 与多数 CPU 测量；锁屏环境下的本轮审查没有完成物理输入、IME、辅助技术和真实显示验收。上述项目需要可交互实机，报告独立状态。

## 统一优化路线与复杂度控制

目标数据流为：事件按语义入队 → 独立状态/字段失效 → 稳定结构只更新动态部分 → 有界增量提交 → 宿主只处理受影响对象 → 平台在帧阶段处理布局和绘制。大文档与数值数据通过版本化数据模型传递，避免反复把完整内容当普通属性。

| 阶段 | 工作包 | 依赖与结束条件 | 复杂度 |
| --- | --- | --- | --- |
| A：建立完整证据 | 12 族代表基线、计时分层、3 个组合负载、产物身份 | 各族均有结果或明确平台缺口；此后每次优化有同轮对照 | 中；一次投入，后续复用 |
| B：消除宿主额外工作 | 04 拓扑按需复制、05 批量顺序、08 定向 widget、09 布局批处理、13 并行加载 | A 对应场景；原子校验/焦点/清理契约通过，小页面无明显回退 | 低至中；内部改动优先 |
| C：缩小 guest 更新 | 01 稳定组件输入、02 派生契约、03 静态内容、06 字段级表单 | 先定稳定输入/失效语义；框架与 kit/文档共用机制；工作量随实际变化增长 | 中至高；本轮核心架构投资 |
| D：重数据与连续交互 | 07 调度语义、10 文档增量、11 数据附件、12 集合/测量 | C 的版本/所有权约定；每个 adapter 共用传输机制；完整输入/IME与生命周期验收 | 中至高；按编辑器、图表、滚动分别交付 |
| E：运行时剩余成本 | 14 对真实 UI profile 的受限 AOT 原型；15 桌面/长期观测 | B–D 后重新排序；仅保留矩阵验证有净收益的方案 | 高；需收益门槛，按证据决定范围 |

阶段 A 先覆盖全部场景族的代表样例，再把更多采样资源放在明显热点；无需等每种设备完成才能推进本地可验证的 B。每个后续工作包都用 A 的矩阵复测，保持小批次、可撤回的交付。

三条架构主线优先保持统一：

- **状态与结构**：组件、派生值、表单、静态文档共用稳定输入和失效规则，避免每个控件自建缓存体系。
- **提交与数据**：拓扑预检查、widget 影响集、版本化大数据共用提交所有权与生命周期，避免场景专用协议分叉。
- **交互与执行**：浏览器连续操作有明确事件/帧语义，执行器提供有界调度；VM/AOT/Worker/桌面沿用相同外部契约。

暂不优先推进全语言重写、完整 Vo→JS 后端、无限帧池、默认全 Worker、场景专用阈值和复杂全局缓存。它们的维护面明显更大，当前可以先通过 UI 的算法、失效范围和数据表示消除已确认的工作。

每项优化的保留条件：输出和输入语义正确、原有生命周期约束通过、目标场景有可重复改善、其他场景无不可接受回退、复杂度与收益相称。整体结果按场景公布，任何几何平均值都须附逐项回退，避免少数漂亮数值遮盖体验问题。

## 已有设计应保留

二进制有界协议、提交前完整预检查、原生输入/IME 的时序保护、稳定 key 和保留身份、LIS 顺序优化、独立虚拟窗口与高度索引、请求去重/取消、optional widget 懒加载、SSR 早期输入捕获、作用域清理、默认关闭诊断，都构成可继续演进的基础。架构优化应收敛在这些共同契约内。

本轮完成的是全场景审查与优化计划，以及上述可复现计数。它没有交付新的产品性能改进，也没有以新探针替代正式交互报告。
