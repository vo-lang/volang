# 局部数组表示与原生别名修正验收 · 2026-09-12

保留局部固定数组直接构造及配套原生别名修正。冻结 v2 产品通过 8,293 项完整正确性检查；61 项 × 7 后端的 11,956 次独立进程执行全部正确，其中正式样本 10,248 次。只有 `codegen-storage` 的字节码与生成镜像发生变化，七种后端耗时下降约 22.5%–47.0%。本结论关闭 C02/R04 的固定数组子项，进一步的动态视图与执行状态优化继续按总计划推进。

## 实现与修正

codegen 根据现有逃逸事实准备独立平铺初始化区间，由局部变量直接接管已验证的同类型区间；避免中间 canonical 数组及第二次局部复制。`OwnedFlatSlots` 明确表示已求值、独立拥有的快照。捕获、地址或视图逃逸、全局与堆字段保持 canonical 表示和真实准入。规范 `runtime-memory.md` §3.4 明确允许这种局部固定数组表示，并保留精确根、求值顺序、真实统计与 sticky 错误。

首版 Native AOT 回归暴露了共享原生分析的两个缺口：平铺帧数组读取可以暴露标量替换对象；间接帧写入后，旧 SSA 常量、别名形状和非空证明可能失效。修正版统一处理帧写范围与候选失效，并用独立 MemoryRead 表示读取结果。真正进入 baseline、optimizing、OSR 的红测及失败 v1 产物均保留。

## 测量口径

旧、新编译器编译完全相同的 61 项源码；两组 VOB 交给同一冻结候选执行器。Native/Core 镜像也使用同一个候选 lowerer，分别配合同一静态运行库或 Core 宿主。因此本轮隔离公共字节码收益，不提供原生别名修正自身的编译成本或完整新旧执行器结论。

每组两次预热、十二对正式样本，按 AB/BA 交替，使用等长输入路径。冷进程时间包含启动、加载/验证、初始化和 guest 执行；构建、准备、诊断及正确性测试均在正式测量之前完成。95% 区间对独立进程对进行固定种子 10,000 次 bootstrap。原始慢样本全部保留，区间没有进行多重比较校正。

平台为 macOS ARM64/M1、Rust 1.94.0、Node 24.16.0。OSR 优先配置设 call threshold=1000、loop threshold=1，60 项有真实循环入口；Fibonacci 无循环，实际进入函数机器码。Native AOT 全部预检有生成代码入口，运行期函数/循环编译及编译耗时始终为零。这里的 Web 性能在 Node 中测量，真实 Chromium 用于正确性验证。
