# Core 整数 Map 查询：完整候选对照 · 2026-09-12

两个私有候选分别与冻结的最终组合 v1 直接配对。整数索引改用完整 64 位乘法的高位，并按当前容量选取有效索引位；组合候选进一步将非浮点单槽键的 8 字节循环比较收敛为一次完整整数比较。浮点、字符串、接口、数组和结构体的语义分支保持在该快路径之前，更宽键保留原来的后备比较。

不改变桶布局、宿主 ABI9、分配准入或扩容规则。增长后通过同一查询函数按新容量重建索引。乘移索引对个别小表序列会增加碰撞，下文完整保留工作量与耗时代价。

## 语义验证

两个候选各通过 33 项 Core 所属测试、1,145 项完整 Core 语言检查。整数索引版通过 77 项宿主检查；组合版加入两个维护的整数／引用键回归后通过 79 项。两版的边界诊断各覆盖十种整数类型、六种容量、满表终止及墓碑，并各执行 424,430 次真实生成查询。组合版实际生成 helper 的 Node 测试计数为 5（堆 1、Map 4），包含于宿主检查中，不能重复累加。

整字比较初稿在新增回归中出现两个失败：把按槽位计算偏移的辅助函数误用成字节偏移。修正采用明确的 8 字节偏移；失败日志保留，初稿从未进入生产源码。当前表格只使用修正后完整通过的候选。
