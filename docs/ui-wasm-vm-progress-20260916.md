# Wasm AOT 清理与 UI 优化进展

2026-09-16。本轮删除 Core Wasm AOT，并继续推进 Web UI 的宿主优化和交付验证。
Web 开发、生产和 Studio 统一使用 Wasm VM；原生 VM、JIT、Native AOT 保留。
此前的 UI 全场景审查和旧性能报告继续作为历史记录，本文记录本轮实际交付。

后续组件、状态、表单、文档、布局与默认命令入口的实现及新一轮性能对比，见
[Web UI 实现与交付进展](ui-web-completion-20260916.md)。本文末尾的工作列表保留上一轮时点。

## 执行路径清理

- 删除 `vo-wasm-aot` 编译器、`vo-aot-support-wasm` 支持库，以及独占的 JS
  堆管理、GC、调度、元数据、标准库适配、UI 适配和测试运行器。
- 移除 Cargo 特性和依赖、编译入口、缓存种类、CLI 构建分支、发布支持包、
  CI/语言测试/benchmark 的 Wasm AOT 分支。Native AOT 的编译和链接路径保留。
- Web 应用产物统一为 `.vob`，配合共享的 Wasm VM；应用自身不再生成 AOT
  `.wasm`。运行时和可选浏览器编译器仍有 `.wasm` 文件。
- 新 UI 工具链和默认项目、分页面入口、SSR、源码重载、Studio 分发及站点
  验收均改为 VM。工具链和旧 UI 部署清单更新到对应 v2 格式。
- 清理公开 JS 导出、模板和当前文档。`build:js` 先清理输出目录，避免升级
  时把已经删除的 AOT 模块再次放入 npm/runtime 包。
- 保留有价值的 GC、递归、退出、标准输入和字节增长用例，迁移到 Wasm VM。
  三个先前只有编译覆盖的 GC 用例现已加入实际执行矩阵。

直接构建 Web 字节码：

```sh
vo build . --kind=bytecode --target=wasm32-unknown-unknown -o app.vob
```

旧 `--kind=wasm` / `--kind=web` 给出迁移说明。新 UI 项目的
`defaultBackend` 可省略或设为 `vm`；旧 `aot` 值报错。自定义宿主需要改为
VM 挂载 API，并更新启动入口和部署产物。历史 AOT 二进制不再受当前宿主支持。

## 本轮 UI 实现

### 拓扑校验只为结构变化准备子节点顺序

文本、属性和祖先命名空间查询借用未变的 children 数组。修改兄弟顺序时，
每个受影响父节点使用一个批次内的前后链接表，最后一次生成数组；删除和移动
不再反复搜索、平移宽数组。完整批次校验失败时仍保持原树不变。

对于固定深度下同一父节点的批量重排，这部分顺序维护由二次增长降为
O(n + m)，n 为原有子节点数，m 为结构指令数。祖先校验、DOM 操作和 guest
协调仍有各自成本，不能把这一复杂度结论扩大到整个 UI 更新。

### 控件按实际依赖接收提交通知

Widget 可以用 `commitTargets` 声明需要读取的原生控件。相关节点及其祖先
变化触发回调；结构变化通知全部控件并重新建立祖先关系。初次安装和新值
仍强制同步，省略声明继续沿用整根通知语义。

编辑器、文件控件及懒加载包装已接入。依赖外部原生 label 的编辑器继续接收
完整通知，以同步标签文字和关联变化；具有显式名称的已增强编辑器才缩小
通知范围。销毁、异常、重入和重挂父节点都有覆盖。结构变更路径同时省掉了
重复收集逐节点集合的工作。

### 并行加载与浮层观察复用

`mountUi` 同时启动应用下载和 VM 加载/初始化，保留共享初始化、取消、失败
重试和根所有权。Popover 只对实际变化的锚点/弹层更新 ResizeObserver，
避免每次提交重新断开再观察。完整的浮层布局读写批处理仍待完成。

### 修复迁移和交互问题

- 受控 popover/dialog 的迟到原生关闭通知可能覆盖用户刚刚重新打开的意图。
  现在根据最后提交的请求过滤回声，继续接收原生外部关闭；快速开关和原生
  关闭均有回归覆盖。
- 编辑器外部标签及关联变化保留同步；读取当前 `label.control` 关系，避免
  Firefox 的 `textarea.labels` 在关联修改后保留旧项。文件控件同时观察字段内
  其他输入的身份变化，保留原有的唯一控件检查。
- 旧 VM 发布包缺少首帧完成回调，导致启动遮罩无法结束。已补齐正常提交和
  reload 的回调链。
- 旧 Studio 未识别新的编译器诊断位置格式，已兼容并验证错误定位跳转。
- Wasm 测试运行器现在把 `exit(0)` 识别为正常完成，同时保留非零退出失败。

## 同轮浏览器性能对比

环境为 Apple M1 Pro、macOS arm64、Node 24.16.0、Chromium 153.0.8010.12。
对照宿主来自本轮开始前的源码快照；两边使用相同应用字节码、Wasm VM、
HTML 和 benchmark 脚本，只替换宿主实现。生产压缩打包，交替先后顺序，
6 轮，每场景每版本 120 个有效样本，共 1,200 次交互；运行期间无并行构建
或测试。每次测量均检查最终值和应保留的 DOM 身份。

测量口径为合成原生事件派发至 DOM 匹配并强制布局，包含 MutationObserver
记录成本，排除实际绘制。单机微基准不能证明全部 UI 场景的体验。

| 场景 | 修改前 p50 / p95，ms | 修改后 p50 / p95，ms |
| --- | ---: | ---: |
| 单行计数 | 1.7 / 6.4 | 1.5 / 6.4 |
| 100 行计数 | 6.5 / 18.2 | 6.6 / 18.2 |
| 反转 1,000 行 | 71.8 / 75.6 | 71.3 / 75.8 |
| 筛选 1,000 行到 19 行 | 20.1 / 25.0 | 19.8 / 24.4 |
| 从 19 行恢复到 1,000 行 | 146.9 / 157.9 | 145.9 / 155.8 |

本轮列表端到端结果总体接近持平。换序 p50 降低约 0.7%、p95 增加约 0.3%；
恢复列表 p50 降低约 0.7%、p95 降低约 1.3%。100 行计数 p50 增加 0.1 ms。
小差异和尾部分布仍有波动，
没有证据支持整体大幅提速。

宿主测得的换序 p50 为 4.6 → 4.3 ms，恢复 p50 为 17.6 → 17.9 ms。
guest 侧计算、描述构建和批次生成尚未在本轮缩减，DOM 工作量及传输字节
也相同。复杂度修复主要避免规模扩大后的额外成本；控件和浮层优化还需要
相应页面的独立计时，不能由这个无编辑器列表页面推断收益。

加载各只有 6 次，中位数 292.7 → 293.4 ms。该 benchmark 直接创建宿主，
未经过 `mountUi`，此数字不能用于宣称并行下载优化的收益。

宿主 JS 为 94,994 → 97,502 字节，gzip 为 29,068 → 29,690 字节，增加
622 gzip 字节。应用和 VM 文件完全相同：

- 应用 SHA-256：`d1013351e4ed2b1c627be9ecc50106ce488e7819d11eb481d7e1856c92c18fbe`。
- VM SHA-256：`9cfccaa74181a8e84434fa022eb343fb2c7f442b6665e4e69c0416a5a7eac723`。

原始样本和产物身份位于
`target/ui-next/host-comparison-20260916/{report,build}.json`。
第一次测量促使我们删除结构提交中重复的节点集合；此前两次测量保存在
`report-before-structural-fast-path.json` 和
`report-before-file-field-dependencies.json`，未与最终数据合并。
