# Core 帧归属优化的隔离结果 · 2026-09-10

本轮保留“每 Island 一份帧登记表，并在释放时传递已有归属”的实现，继续进入下一批七后端验收。递归树的冷启动耗时下降8.70%；二叉树均值下降0.69%，区间包含零，尚未证明稳定提速。五个分配/视图负载的冷启动变化均在约±0.15%内。热执行仍有小幅波动，不能据此宣称每项都提速。

## 改动与正确性

此前全局 Map 保存帧布局，每个 Island 再用 Set 保存相同帧的根身份。合并为按 Island 持有的 Map 后，布局仍来自宿主已登记的函数，根的次序和回收语义保持。第一次原型在回收普通对象时额外查询 span 归属，导致多个分配负载变慢。最终候选让 collector 回调、Island 清理和显式释放传入已经解析的 owner，删除了这些重复查询。没有改变字节码、Native ABI、Core host ABI、实际 managed 分配、GC预算或失败行为。

最终候选通过 TypeScript、56项宿主测试及6负载的精确 managed/GC/调度计数对照。另有12次独立插桩执行保持输出和计数一致：第一次原型在allocator-shapes、append-growth、jit-slice、map-lifecycle的释放路径分别增加209699、524348、461803、195106次归属查询，最终候选四项均为0；每个程序总查询数比原始宿主多1次，来自冷的宿主调用布局解析。第一次原型另通过1140项Core语言用例；这个结果不替代最终候选在C08/VOB22新产物上的完整语言与浏览器检查。
