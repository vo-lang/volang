# Map 查询工作区优化 · 2026-09-12

R06 的查询工作区优化已完成8,347项完整产品检查、98万次实际查询计数和4,312次正式对比执行。接口键和宽数组键的收益明确；三项控制负载回退仍需独立复测，本子项的最终性能验收保持开放。

旧路径对每次接口键查询创建可比较性遍历容器；聚合键的哈希与比较分别创建工作栈、访问集合及哈希结果数组。数组查询仅需物理宽度，却会重新展开完整槽位布局，未复用加载时的类型事实。

现在标量类型直接判定可比较性；小型类型图和遍历工作栈使用固定容量的栈存储，大型图按需转入迭代工作栈和哈希集合。一次深度优先哈希遍历只需保存一个待合并结果，改为单个可选值。借用类型视图携带所属加载模块既有的宽度事实，表字段改为只读访问方法，防止替换表后仍使用旧事实。构造期原始类型表继续使用原有的检查式展开。新增 smallvec 使用仓库已锁定的1.15.1，没有升级依赖。

哈希算法、字段顺序、浮点正负零、NaN、不支持比较的动态类型、托管堆分配和GC规则均保持原契约。类型事实已由LoadedModule拥有，本次未增加常驻类型缓存或新GC根。
