# 运行时诊断统一入口验收 · 2026-09-11

G01 已将布局资源、GC 根延迟和父 Island 调度接入 `vo-dev bench diagnostics`。新增入口的 312 次执行、旧快照的 27 次回放及 16 项专项检查全部通过。本报告验收测量工具的可复现性与结果校验，不据单次自对照推导性能收益。

## 实现与责任边界

诊断目录现在有八类：compile、pipeline、regions、transfer、recycling、layouts、roots、island。探针仍归各自 crate 所有，控制工具负责准备、身份校验、执行和统计。详见[使用说明](benchmark-diagnostics.md)。

- 准备阶段冻结真实 CLI、源文件、输入字节码和探针；带分配计数与普通计时的产物分开构建。内容寻址的临时源路径保证相同输入具有稳定的调试文件名。
- 执行阶段复用冻结输入，使用等长路径；比较要求源码和 VOB 字节一致。每次运行同时绑定控制工具自身的哈希。
- 模式、负载、样本序号、布局事实、精确输出、校验和及真实 JIT 入口均校验。GC 初始请求按实际完成工作记账，后续每次宿主返回独立记录；最终恰好观察到一次目标 guest 输出。
- 内部重复先汇总为一个进程样本。分配计数产物的时间不进入耗时汇总，零预热的接口验证也不产生尾延迟或置信区间结论。
- 快照 schema v3 新增冻结输入和编译器；保留既有 v1/v2 读取与执行。普通生产运行时没有增加诊断计数器或依赖。

## 实际验证

| 范围 | 单版本执行 | 相同快照配对执行 | 覆盖 |
| --- | ---: | ---: | --- |
| 布局资源 | 18 | 36 | 3 个输入 × 3 种视图，计时/计数分开；每进程 25 次加载和克隆 |
| GC 根延迟 | 56 | 112 | 7 种全局/Fiber/defer 根规模 × VM/JIT × 2 种 GC × 强制/控制；每进程 512 次观察 |
| 父 Island 调度 | 30 | 60 | 0/1/8/32/128 子 Island × VM/baseline/optimizing × idle/busy；每进程 256 个批次 |
| 旧 v1 快照回放 | 25 | — | 原编译、region、transfer、recycling 入口 |
| 旧 v2 快照回放 | 2 | — | pipeline 的独立计时和计数入口 |

新增入口共 312 个进程，包括 86,016 次 GC 根观察、23,040 个父调度批次，以及 1,350 次布局观察。探针保留原有内部预热行为，预热执行未逐项保存，也未计入这些观察数。每种配对只有一个独立进程样本，工具没有生成 bootstrap 区间。三类汇总分别包含 18、224、30 个统计项。

16 项专项检查覆盖缺失输入、替换字节码、错误选择器、计数泄漏、不完整或重复样本、GC 工作与时钟归属、缺失机器码入口、旧字段兼容和进程样本归并。两份 Engine 示例通过编译检查。实际准备、执行和回放均使用 M1/macOS；本报告不建立另一原生架构或 AOT/Web 执行性能结论。
