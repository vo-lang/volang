# Web UI 实现与交付进展（2026-09-16）

本轮完成新 UI 框架的更新边界、Studio 消费接入和公开工具包的本地交付收尾，
最终全套验证已通过。Web 使用 Wasm VM；Core Wasm AOT 已在上一轮删除，原生 JIT / Native
AOT 保留。本文接续 [上一轮报告](ui-wasm-vm-progress-20260916.md)。

## 本轮实现

| 范围 | 实现与正确性约束 |
| --- | --- |
| 组件更新 | `View.Memo(inputs...)` 显式声明稳定输入；保留最新渲染闭包，组件自身状态、脏子组件、上下文变化仍正常更新。元数据使用可选对象，普通视图只增加一个指针槽。 |
| 上下文与派生值 | 订阅最近提供者及中间缺席的提供者；新增、移除、替换提供者能穿过跳过的组件通知消费者。`DerivedMemo` 按声明输入和响应式依赖失效，卸载释放捕获及输入。 |
| 状态与表单 | `Store.Select/SelectEqual` 按不可变投影订阅；比较与选择禁止响应式写入。`Form.Field` 隔离字段订阅，独立校验器只检查改动字段；跨字段及异步校验保留完整语义。 |
| 文档与图表 | 文档 `Prepare/Parse` 和图表 `Prepare` 生成不可变内容；按内容身份复用，避免无关刷新重复验证、构建和编码。Studio Docs 与公开 plot 示例已接入。 |
| 布局与输入 | 每个 root 共享尺寸观察、视口观察和帧调度；浮层按依赖分层，批量读取尺寸后写入位置。输入每批最多 128 个事件，批次间让出线程；pointermove 可显式合并连续同指针样本，保留事件屏障。 |
| Studio | Gallery 静态组件使用稳定输入，表单按字段订阅，Docs 缓存已准备的章节。Gallery / Playground / Docs 继续作为展示入口。 |
| 工具入口 | 含 `ui-next.json` 的目录直接支持 `vo ui dev/build/test`，也支持目录参数；错误配置直接诊断。显式 `--project`、帮助、旧项目命令和原生入口保留。 |

协议升级到实验版本 25，生成的 Vo / TypeScript 编解码同步更新；应用与宿主需要
一起构建。普通输入保持 FIFO，最新指针样本交付需要应用显式选择。

接口、失效约束和使用说明位于 [状态指南](../ui/next/guides/state.md)、
[表单](../ui/next/forms/README.md)、[文档](../ui/next/document/README.md)、
[图表](../ui/next/web/plot/README.md) 和 [迁移说明](../ui/next/migration.md)。

## 同轮性能对照

基线为本轮开始时的工作区快照，已经包含上一轮宿主优化及 Wasm AOT 删除。
前后共用同一份 Wasm VM。机器为 Apple M1 Pro，macOS arm64，Node 24.16.0，
Chromium 153.0.8010.12。测量期间串行运行，无并行构建或功能测试。
前后源码放在独立模块目录，目录路径保留在各自产物的调试元数据中。

列表测试交替运行旧、新版本各 6 轮；每轮每场景 20 个有效样本，另有 3 次预热。
每个版本每场景共 120 个样本，同时检查输出、节点身份、DOM 修改数和传输量。
计时从原生事件派发到匹配的 DOM 结果及强制布局，未计入绘制。

| 场景 | 旧 p50 / p95（ms） | 新 p50 / p95（ms） | p50 变化 |
| --- | ---: | ---: | ---: |
| 单行更新 | 1.7 / 5.8 | 1.6 / 6.9 | −5.9% |
| 更新 100 行 | 6.5 / 17.8 | 6.7 / 16.8 | +3.1% |
| 重排 1,000 行 | 71.2 / 76.1 | 30.7 / 38.3 | **−56.9%（2.32 倍）** |
| 1,000 行筛选至 19 行 | 19.6 / 24.3 | 19.5 / 23.7 | −0.5% |
| 19 行恢复至 1,000 行 | 147.2 / 156.8 | 150.1 / 166.7 | +2.0% |
| 100 字段表单编辑一项 | 9.6 / 10.1 | 4.6 / 6.6 | **−52.1%（2.09 倍）** |

负值表示耗时减少。列表新版显式采用 `.Memo(id, bulk)`，其余可观察语义一致。
表单两侧使用完全相同的应用源码和完整表单校验器，各 180 个有效样本；此表的
收益没有使用新增的独立字段校验器捷径。

初次加载各 6 个样本，中位数为 293.4 → 307.1 ms（+4.7%），p95 为
338.8 → 319.1 ms。该项样本少、仅本机无压缩 HTTP，进程和 Wasm 缓存可能已热，
不能据此判断真实冷启动或移动设备表现。单行更新的 p95 增加 1.1 ms；批量恢复也
有回退，均保留在结果中。显式缓存有额外分配和比较成本，其收益集中于复用已有
组件；本轮没有得到所有场景都变快的结论。

列表交付文件合计 3,626,916 → 3,641,229 字节；潜在 gzip 合计
1,267,287 → 1,271,920 字节（+0.37%）。VM 本体保持相同。千行重排前后都产生
3,996 条 DOM 观察记录、33,004 字节 guest 输出及 1 个提交批次；主要收益来自
减少 guest 重建工作。

另有运行计数断言：父级刷新时，100 个未变输入的子组件从 100 次渲染降到 0 次；
无关更新引起的派生计算从 1 次降到 0 次。百字段用例编辑一项时，只有对应字段
渲染、执行独立校验并输出一个值修改，表单所有者保持不变。工作计数与延迟分开记录。
