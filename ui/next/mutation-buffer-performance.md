# 渲染批次缓冲区：AOT 列表尾延迟

> 2026-09-16：已决定移除 Core Wasm AOT。本文中的旧 AOT 测量保留为历史记录；当前 Web 执行和后续优化统一使用 Wasm VM，原生 JIT / Native AOT 继续保留。旧后端的源码引用对应删除前版本。

2026-09-16。这次调整仅改变 `Root` 收集待提交指令的内部结构。公开 Batch、wire v24、
组件协调、事件时序和 GC 算法均保留。结果来自同机、同浏览器的前后对照，完整归档
入口为 [feature-v24-mutation-buffer](../../target/ui-next/benchmark/experiments/feature-v24-mutation-buffer/README.md)。

## 原因与实现

先用未插桩的实际生产镜像观测两轮恢复，计时结束后读取已有内存计数。AOT 每次
分配约 113.6 MB，但慢样本约 900 ms、快样本约 350 ms，扫描工作分别约 1,570 万
与 110–150 万单位。单独的 CPU 采样指向引用扫描；进一步的宿主计数表明，慢样本
约 1,474 万次扫描来自 `[]Mutation`，快样本同类扫描约 20–23 万次。其描述符确认为
48 字节、三个引用字段，与协议的 Mutation 布局一致。插桩运行只用于定位，耗时
未计入性能对照；guest 镜像字节与未插桩版本相同。

原实现逐条 `append` 指令。在当前 Core AOT 的切片表示下，这会产生不断加长的
切片视图；活跃 GC 周期保留其中一部分，反复扫描重叠前缀。新私有缓冲区在容量
不足时按倍数增长，平时按位置写入，提交时切出有效区间并转交所有权。下一次渲染
使用新缓冲区，错误边界回滚会清空被丢弃的记录，避免保留无效引用。

实现约 40 行，保留原有 `emit` 调用层级。首个试验把 `emit` 再转交给 `push`，增加了
高频调用与分配；该中间版本单独归档，最终实现合并了这层调用。没有引入跨批次池、
场景专用阈值或第二套协议。

## 最终同轮对照

Apple M1 Pro、Darwin arm64、Node 24.16.0、Chromium。同一 CLI、应用源码路径、
浏览器宿主与 VM Wasm；三轮轮换，五个场景，每轮每场景 20 次有效样本，先预热三次。
四个 driver 为前后版本 × VM/AOT，共 **1,200 个样本**。计时涵盖合成原生事件至
正确 DOM 和强制布局，包含 MutationObserver 记录成本，排除绘制。测量期间没有
并行编译或浏览器回归。全部样本验证输出、适用场景的保留节点身份与关闭行为。

下表为 **p50 / p95（ms），原实现 → 缓冲区**：

| 场景 | Wasm VM | Core Wasm AOT |
| --- | ---: | ---: |
| 单行计数 | 1.4 / 7.5 → 1.3 / 6.0 | 1.2 / 1.5 → 1.3 / 1.8 |
| 100 行计数 | 6.8 / 14.9 → 6.7 / 18.9 | 14.5 / 31.2 → 14.8 / 35.4 |
| 1,000 行换序 | 75.3 / 84.2 → 72.0 / 82.6 | 183.1 / 192.8 → 190.3 / 205.2 |
| 筛选 1,000 → 19 | 20.7 / 24.0 → 20.7 / 27.7 | 48.1 / 53.6 → 50.6 / 83.0 |
| 恢复 19 → 1,000 | 149.2 / 168.8 → 149.9 / 166.3 | 343.1 / 889.5 → 318.7 / 348.0 |

AOT 恢复 p50 下降 **7.1%**、p95 下降 **60.9%**。VM 恢复 p50 变化 +0.5%，没有
明显提速。AOT 换序 p50 增加 3.9%，筛选 p95 从 53.6 增至 83.0 ms；VM 批量计数
p95 从 14.9 增至 18.9 ms。全部分位数都列出，不能把恢复收益推广到每个交互。
采用该实现的依据是：通过一个小型内部数据结构，消除了本轮可重复出现的最大停顿。
大列表绝对耗时、批量更新和筛选尾部仍有优化空间，原有性能预算继续开放。

每轮 AOT 更新的累计分配从 **4,790,673,730** 降至 **4,766,548,506 字节（0.5%）**；
GC 工作从 **154,902,329** 降至 **35,136,494 单位（77.3%）**。这些计数在三轮相同。
更新结束时 committedBytes 从 62,193,664 降至 56,819,712，liveBytes 从 21,497,429
降至 14,381,769；观测前没有强制完整 guest GC，不能据此推断长期占用或泄漏。

相同宿主的完整页面 gzip 字节增加 VM **521**、AOT **1,376**。每版本仅三次挂载，
p50 分别为 VM 308.6 → 318.6 ms、AOT 315.5 → 319.0 ms，样本不足以判定加载差异。
同轮 Vue/Svelte、真实设备输入、移动 CPU、网络限速和 field INP 未测量。

## 回归与复现

永久运行时用例验证大批次增删、空更新、错误边界丢弃大量未提交操作、重试、关闭，
并在后续所有操作结束后重新编码保存的旧 Batch，确保其字节没有变化。用例进入
既有原生 VM/JIT 与 Wasm VM/Core AOT 聚合入口；完整浏览器与交付结果以归档记录为准。

归档保留源码副本、前后实际镜像、构建 SHA-256、所有样本、CPU profile、扫描计数
和中间版本。`build.mjs` 与 `run.mjs` 从仓库根运行，使用记录的 release CLI、锁定依赖
与浏览器；隔离目录在脚本内声明。复测须使用新的工作目录，保留原始归档不变。
