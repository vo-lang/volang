# Studio 性能测量

2026-09-18，在同一台 Apple M1 Pro（10 核、macOS arm64）、Node 24.16.0、
Chromium 153.0.8010.12 上，对保留的修改前静态分发与当前静态分发分别运行测试。
两次执行均使用 Wasm VM。当前分发包含 Worker 执行、24 个文档章节、目录和代码复制。

## 结果

单位为毫秒，表内为 **p50 / p95**。

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 冷加载就绪 | 512.5 / 516.9 | 485.8 / 527.9 |
| 暖加载就绪 | 500.6 / 503.8 | 477.7 / 479.4 |
| 计数按钮 | 1.5 / 3.3 | 1.5 / 5.1 |
| 主题切换 | 3.2 / 4.7 | 3.7 / 5.3 |
| 打开弹窗 | 3.3 / 4.6 | 3.1 / 4.1 |

冷加载中位数降低约 5.2%，暖加载降低约 4.6%，弹窗降低约 6.1%。计数按钮中位数
持平，主题切换中位数增加 0.5 ms；计数按钮 p95 增加 1.8 ms，冷加载及部分交互
尾延迟也有波动。结果显示启动略有改善，交互没有稳定的全面提升。

此前对中间构建的同规格复测得到冷/暖加载 483.7/470.2 ms、主题 3.0 ms、弹窗
2.9 ms。该轮样本也保留在下方；主表使用最终重建产物，不挑选最好的一轮。

当前冷加载响应字节中位数为 1,637,890，暖加载为 5,404，包含 Worker 请求。
修改前使用页面 Resource Timing；当前改为浏览器上下文请求统计，包含响应头与
压缩响应体。两者口径不同，不比较下载量变化。Gallery 没有预先下载可选编译器或编辑器。


## 方法与限制

入口为规范 Gallery 路径，视口 1280×900，本机 HTTP 使用真实 Brotli/gzip 协商。
三轮测量各在新浏览器上下文中冷加载，再在同一上下文新开一页暖加载。每个场景先预热
三次、测量二十次，冷暖合计每场景 120 个样本。交互计时从合成原生点击到目标 DOM
状态并强制布局，不包含绘制和可信输入开销。弹窗只计打开，关闭等待完整退出动效。

加载每组只有三个样本，p95 就是最大值。修改前后分开执行，系统和 Wasm 缓存可能
已热；结果不能用于推断显著性、移动设备、弱网或线上 INP/LCP。Worker 让 guest
执行离开文档线程，但其收益仍取决于实际工作负载。这次没有引入额外运行时缓存或
复杂编译优化，也没有把功能验收等同于性能测量。

## 2026-09-20：线上冷启动诊断与交付修复

此前本地压缩协商测试没有覆盖 Pages 实际传输。线上曾连续测到 22.8 / 25.4 秒
就绪：约 1.79 MB 字节码未压缩传输，运行时的小 JS 依赖迟迟未响应，Wasm 下载
直到约第 14 秒才开始。资源请求等待占主要部分，无法据此判定 VM 执行本身很慢。

修复后的发布版直接下载 `studio.vob.gz`，由独立 Worker 解压，兼容服务器已经通过
Content-Encoding 解压的响应。Wasm 请求在导入运行时绑定之前发起，初始化与
字节码下载并行。开发服务器继续使用原始字节码，不依赖预压缩构建。
文档缓存提升至应用作用域，保留 24 项 / 8 MiB 的界限；链接聚焦或非触摸悬停时预取。

[线上资源对照原始样本](benchmarks/studio-startup-20260920.json)：每组 3 个新浏览器
上下文，旧方式 3221 / 1524 / 1310 ms，新方式 1257 / 1902 / 1200 ms。
两种 Worker 均在本地同方式打包并通过浏览器请求覆盖，其他资源来自线上；这不是
部署后的验收。浏览器进程、网络中间层可能已经热，且功能测试同时运行，时延只作
诊断，不能作为稳定提速百分比或“24 秒降到 1 秒”的证据。

可确认的交付变化是字节码响应体从约 1.79 MB 降到 0.65 MB（约减少 64%），
且 Wasm 已不再等待绑定脚本。三浏览器静态验收通过主动阻塞绑定脚本检查请求顺序，
并验证启动后的真实按钮交互、文档按需预取及离开文档再返回时不重复请求。
正式上线后仍需以实际发布资源重测冷启动与受限网络，不沿用本地数字。
